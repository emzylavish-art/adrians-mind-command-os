# Build order

This is the order for four systems. It is not an implementation, and it is not permission to start a Windows build. Nothing in this list is started until you say execute.

The four systems are the Permission Center, the AI Hub, the Build Engine, and the local execution service. They come before the installer, HyperFrames, the glass redesign, and the GitHub tool sweep. A later system does not start until the one before it has a real test, not a screen that only looks finished.

## 1. Permission Center

This comes first because every later system asks for access. Credentials, file writes, terminal commands, and a future PC companion all need the same gate.

When this phase is executed, it records who asked, what they want, whether you approved that exact action, and whether the emergency stop is on. You can approve, deny, revoke, or limit a permission. EVE cannot approve one or press the stop. A denied action does not run. The screen must not say Windows granted a permission when Windows has not.

The proof that ends this phase is a denied action that does nothing, and one approved hosted action that does run. That proof does not exist as a Permission Center yet. The current owner flow is only the hosted file and terminal gate.

## 2. AI Hub

This comes second so Build and the agents call one router instead of a single hardcoded provider. It does not come before the permission gate, because stored keys are access.

When this phase is executed, you can add a provider, enter a key, test the connection, pick a model, and disconnect it. A missing key is reported as unavailable. A model is not marked able to see, hear, or call tools unless a connection test shows that. New paid providers stay in zero-spend until you opt in. No credits are purchased. Grok stays connected on the path that already works. Fallback to another provider happens only under a routing rule you approved, and confidential text is not sent elsewhere without that rule.

The proof that ends this phase is the existing Grok reply still returning, plus one missing provider shown as unavailable rather than pretended.

## 3. Build Engine

This comes third because it already exists. It is preserved, not replaced. It calls the hub and the permission gate. It stays on the hosted workspace until the local service exists.

When this phase is executed, the check is the one already named in the stored plan: open a test project, read a file, change it, run the build, find the error that change introduced, fix it, run tests, launch a preview, verify the result, and save it. Only that sequence can be called operational. The hosted file read, write, delete, and terminal command remain the four actions that can run today, each after you approve that exact action.

The proof that ends this phase is that acceptance sequence on the hosted workspace. It has not been run as that sequence.

## 4. Local execution service

This comes last of the four. It is the first system that could touch a Windows PC, so it waits until the Permission Center can refuse and the Build Engine has a tested hosted path to fall back on.

When this phase is executed, it is a separate companion, not code in the website that pretends to move a mouse. It can propose a file read, file write, file delete, or terminal command on an already paired computer. You approve the exact action. The emergency stop refuses it. Mouse, keyboard, screen reading, and browser control on your PC stay refused until you approve those permissions and a companion is actually installed. Closing the Adrian window must not be described as keeping a PC task alive until that companion exists and a test shows it.

The proof that ends this phase is one owner-approved file or terminal action on a paired computer, and one mouse request that is refused. No computer is paired today, so this phase cannot be called done.

## After these four

The Windows installer, startup tray, HyperFrames, the glass design system, the department agents, and the GitHub tool sweep wait until these four have their proofs. A package install is not a working department. A download is not a permission Windows has granted.

What already runs, and must not be thrown away while this order is waiting: Speak as a system call, the in-tab microphone that stops when the tab closes, the owner emergency stop, and the four hosted actions after exact approval. The body is a clothed figure with your saved face. It is not a finished person, and this roadmap does not change that.
