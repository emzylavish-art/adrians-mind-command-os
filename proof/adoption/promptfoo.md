# Promptfoo

Candidate id: promptfoo. Name: promptfoo. Classification: evaluation-only. This note does not approve or install it.

Official source: [promptfoo/promptfoo](https://github.com/promptfoo/promptfoo). The repository is public, not a fork, not archived, and not disabled. Its homepage is [https://www.promptfoo.dev/](https://www.promptfoo.dev/). The npm package `promptfoo` names that same git URL and homepage, and names Ian Webster as author. [1] [2] [3] PyPI `promptfoo` is a different package. Its project URL is `promptfoo/promptfoo-python`, and its own text says it runs `npx promptfoo@latest`. That wrapper is not the candidate. [4]

Version: npm `latest` is `0.125.1`, published `2026-10-25T02:12:24.374Z`. The only dist-tag in the registry record is `latest`. GitHub `releases/latest` is tag `0.125.1`, published `2026-10-25T01:53:11Z`, not a draft and not a prerelease. The version strings match. The release target is commit `8569e72ed6cf7737082a6042be8d925e40f9739d`. `package.json` at that tag is version `0.125.1`. The npm record has `gitHead` null, and the tarball was not unpacked, so byte identity between the tarball and that commit is unverified. `main` still says `0.125.1` in `package.json`, but the compare of tag `0.125.1` to `main` was 300 commits ahead and 0 behind. The newest commit in that compare was `5fac53eefdd2`, dated `2026-11-15T08:27:31Z`. PyPI latest is `0.2.0`, uploaded `2026-09-18T19:52:49.745670Z`. It does not match npm `0.125.1`. [3] [5] [6]

It says a probe is one request to the target during red team testing, and that some plugins use hosted inference. Exact Adrian Mind usage is unverified. The website terms, last updated 2025-01-24, restrict the site and its content, including a personal non-commercial grant for site content. Those terms are not the LICENSE file of the npm package. This research created no account and spent no money. [7] [8] [9]

The package type is `module`. The bins are `promptfoo` and `pf`, both pointed at `dist/src/entrypoint.js`. The main entry is `./dist/src/index.js`. Docs show `evaluate()` as the library call. It can also start a local web viewer and an MCP server. SECURITY.md says those local interfaces run with the user's permissions and are not a multi-user boundary. None of this was executed. [3] [12] [13] [14]

The PyPI wrapper text says a first `npx` download is typically about 50 MB. That is not a measurement of this tarball. [3] [4] [10]

Optional peers include `playwright`, `@openai/agents`, and `@openai/codex-sdk`. The published record has no `preinstall`, `install`, or `postinstall` script, and no `_hasInstallScript` field. Whether a consumer install would run `prepare` was not tested. Security: the GitHub advisory query for npm package `promptfoo` returned an empty list. The repository security-advisories list was empty. An OSV query for npm `promptfoo` version `0.125.1` returned no vulnerability objects. The PyPI wrapper record also listed no vulnerabilities. That wrapper is not this package. No malware scan of the `0.125.1` tarball was run, so an empty advisory list is not a clean-bill scan. SECURITY.md says the tool is permissive by default. Custom assertions, script providers, transforms, hooks, plugins, and templates that execute code are not sandboxed. It supports the latest published npm or Docker release, treats `main` as best effort, and does not backport fixes to older releases. [14] [15] [16] [4]

Secrets: a model evaluation needs that provider's key. The privacy notice says local CLI and library calls go to the configured model provider, and that Promptfoo does not see those requests unless the user grants access. It also says telemetry is on unless changed, and that an opted-in SimulatedUser or red-team path can send prompts to Promptfoo servers. The data-handling page says that, without `OPENAI_API_KEY` or a usable Codex or ChatGPT login, generation and grading go to `api.promptfoo.app`. That payload can include the purpose, plugin settings, the prompt, the target response, and an email used for usage tracking. `promptfoo redteam poison` sends document contents even when an API key is set. Auth headers pasted into red-team setup forms are sent. Telemetry goes to `a.promptfoo.app`. `PROMPTFOO_DISABLE_TELEMETRY=1` disables the documented telemetry path. It does not disable account, license, sharing, or hosted-inference calls. Sharing can upload inputs and outputs. The privacy notice says shared inputs and outputs are stored for two weeks. Local history and cache go under `~/.promptfoo`, or under `PROMPTFOO_CONFIG_DIR` if set. No secret was read or written for this check. No installer script was run. [17] [18] [14]

Integration: Adrian Mind does not import promptfoo. `package.json`, `package-lock.json`, `pnpm-lock.yaml`, and `src` have no promptfoo reference. `docs/arcanum-ai-security-learning-path.md` names Promptfoo in a tool list with Garak, PyRIT, and FuzzyAI. That sentence is not a dependency and was not changed. Adding promptfoo would be a new local eval runner, not an upgrade of Chat, Build, Human Code, EVE, or Speak. It was not added. Eve and every bot still share one workspace memory. This package was not given a second brain, a secret, or a halt control.

Compatibility: the product has no `engines` field. The sandbox Node is v22.23.4, which meets `>=22.22.0`. The product is ESM. Its TypeScript range is `^5.7.0`. The lock resolves `zod` at `4.6.7`, which satisfies the candidate's `zod` range. The product already has Playwright `^1.62.0` as a dev dependency. Promptfoo lists Playwright as an optional peer. Whether both can run in the Vite preview was not tested. The product's saved model provider was not wired to a Promptfoo provider, so that fit is unverified.

Risks: the CLI can execute configured JavaScript or Python, read files through configured tools, run git through `simple-git`, and open a local web UI or MCP server. An optional dependency is a filesystem MCP server. Those paths can do more than the owner-approved paired actions, which are only `file_read`, `file_write`, `file_delete`, and `terminal`, and only after approval of that exact action. Halt would not become a control over those paths. Mouse, keyboard, browser pointer, and the Windows desktop stay blocked, and this package was not given any of them. Default red-team generation can send prompts, target responses, and pasted credentials to Promptfoo servers. A `~/.promptfoo` database would be a second local store, outside the shared workspace memory. The PyPI wrapper tracks `npx promptfoo@latest`, and `main` is 300 commits ahead of the tag while still named `0.125.1`. A later trial has to pin npm `promptfoo@0.125.1`, not `main`, not `latest`, and not the PyPI wrapper. No code review of the tarball was done.

Maintenance: the supported release, by SECURITY.md, is the latest published npm or Docker release. That release is `0.125.1`, dated 2026-10-25. `main` moved again on 2026-11-15 and is not a separate published version. Fixes are not backported. Support beyond that policy page, and the status of the announced OpenAI acquisition, are unverified. [14] [11]

Rollback: do not add `promptfoo`, do not run `npx promptfoo`, do not `pip install promptfoo`, and do not start its viewer, MCP server, or a Cloud share. If a later trial does, remove the added package from the manifest, stop any viewer or MCP process started for the trial, and delete only the `~/.promptfoo` directory or `PROMPTFOO_CONFIG_DIR` created for that trial. Do not delete product `.data`. Nothing was installed, so there is no package or directory to remove.

Classification: evaluation-only. Identity is confirmed. The npm package and the GitHub latest release are the same version string, `0.125.1`. The MIT license does not block review. No published advisory was found for `0.125.1`, so this candidate is not blocked by an advisory. It is not approved and not installed.
