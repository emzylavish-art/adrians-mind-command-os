# Official MCP TypeScript SDK

Candidate id: mcp-sdk. Name: official Model Context Protocol TypeScript SDK. Classification: evaluation-only. This note does not approve it and does not install it.

Official source: [modelcontextprotocol/typescript-sdk](https://github.com/modelcontextprotocol/typescript-sdk). The repository is public, not archived, and not disabled. Its description is "The official TypeScript SDK for Model Context Protocol servers and clients." The official SDK page lists that repository as the TypeScript SDK and marks it Tier 1. [1] [2] The hinted npm package is `@modelcontextprotocol/sdk`. Its registry record points at the same GitHub repository. This is not the Python SDK, and it is not a third-party wrapper.

Version: GitHub and npm do not name one number. Neither line is chosen here as installed. The GitHub latest release is tag `v2.4.0`, named `2.4.0`, published 2026-10-23T18:32:25Z, not a draft and not a prerelease. That release lists `@modelcontextprotocol/client` 2.4.0, `@modelcontextprotocol/server` 2.4.0, `@modelcontextprotocol/core` 2.4.0, `@modelcontextprotocol/server-legacy` 2.4.0, and `@modelcontextprotocol/codemod` 2.4.0. `@modelcontextprotocol/node` is listed at 2.1.2. Express, Hono, and Fastify are listed as unchanged. [3] npm `latest` for those split packages matches 2.4.0 for client, server, and core, published 2026-10-23T18:21:05.614Z, 2026-10-23T18:20:13.773Z, and 2026-10-23T18:19:54.299Z. The hinted package is a different line. npm dist-tag `latest` for `@modelcontextprotocol/sdk` is 1.32.2, published 2026-10-23T18:11:38.362Z. The `v1.x` branch `package.json` also says `"version": "1.32.2"`, and its commit `3b73021a0a2272c0c04c3917bcdb03398b3ec63f` matches the npm `gitHead`. The `main` workspace `package.json` is `"private": true` and says `"version": "2.0.0-alpha.0"`. That root version is not a published package. The README says `main` is v2, while v1 lives on `v1.x` as `@modelcontextprotocol/sdk`. [4]

License: mixed, and GitHub's SPDX field is `NOASSERTION`. The `main` LICENSE says new code and specification contributions are Apache-2.0, documentation other than specifications is CC-BY-4.0, and MIT-licensed contributions stay MIT until the author consents to relicensing. Copyright on the MIT text is 2024-2025 Model Context Protocol a Series of LF Projects, LLC. The `v1.x` package file and the npm 1.32.2 record both say MIT, with author Anthropic, PBC. The published 2.4.0 client, server, and core records say Apache-2.0. The README says new contributions are Apache-2.0 and existing code remains MIT. [5]

Commercial: no paid SDK tier was found on the official SDK page or the package records. MIT allows use, modification, and sale if the copyright and permission notice stay with copies. Apache-2.0 allows commercial use and distribution if the license, change notices, and required NOTICE text stay with the work. Its patent license ends for a party that files patent litigation claiming the work infringes. CC-BY-4.0 covers documentation other than specifications and requires attribution. Whether specifications have a separate license text beyond the transition notice is unverified. No account was created and no money was spent.

Runtime: TypeScript libraries for MCP clients and servers. The README says the SDK runs on Node.js, Bun, and Deno, and ships stdio and Streamable HTTP plus optional Express, Fastify, Hono, and Node HTTP adapters. That Bun and Deno claim was not executed. v1 `@modelcontextprotocol/sdk` 1.32.2 is `"type": "module"`, with ESM and CommonJS exports, and engines require Node.js `>=18`. There is no bin. v2 `@modelcontextprotocol/server` and `@modelcontextprotocol/client` 2.4.0 are also `"type": "module"`, with `.mjs` and `.cjs` entries, and engines require Node.js `>=20`. The private `main` workspace file also says Node.js `>=20`. Tool schemas on v2 use Standard Schema. v1 still depends on Zod directly.

Peer dependencies are `zod` `^3.25 || ^4.0` and optional `@cfworker/json-schema` `^4.1.1`. It overrides `qs` to `6.14.1` and resolves `strip-ansi` to `6.0.1`. Its scripts include `prepack`. They do not include `preinstall`, `install`, or `postinstall`. The private `main` workspace has a `prepare` script that runs `lefthook`. That script is not on the published 1.32.2 record. The 2.4.0 server record depends on `zod` `^4.2.0` and `@modelcontextprotocol/core` `2.4.0`. The 2.4.0 client record depends on those plus `jose`, `cross-spawn`, `eventsource`, `pkce-challenge`, and `eventsource-parser`. Those published script lists also omit `preinstall`, `install`, and `postinstall`. Transitive dependency risk was not audited.

Security: the first page of published GitHub advisories does not place 1.32.2 or 2.4.0 inside a vulnerable range. A high advisory, [GHSA-6qxp-vccf-f47h](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h), covers an OAuth client sending stored credentials to an authorization server named by the MCP server, for `@modelcontextprotocol/sdk` `>= 1.12.0, < 1.31.0` and `@modelcontextprotocol/client` `>= 2.0.0, < 2.2.0`. A medium advisory, [GHSA-rvq5-wwqv-78pq](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-rvq5-wwqv-78pq), covers server bearer tokens issued for another service, for the SDK below 1.32.0 and the server package below 2.3.0. Its text says the added `expectedResource` check stays off unless the application sets it. A high advisory, [GHSA-22jm-h49p-29qw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-22jm-h49p-29qw), covers experimental tasks not tied to a session, for the SDK `>= 1.24.0, < 1.32.0`. A high advisory, [GHSA-jm63-cq47-j5jp](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-jm63-cq47-j5jp), covers shared server or transport instances mixing HTTP clients, for `@modelcontextprotocol/server` `>= 2.0.0, < 2.3.0`. A medium advisory, [GHSA-6prh-2h8m-c8cw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6prh-2h8m-c8cw), covers cross-origin redirects that resend headers and bodies, for the SDK below 1.32.0 and the client below 2.3.0. A high advisory, [GHSA-46jr-4wx8-v453](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-46jr-4wx8-v453), covers memory exhaustion during validation, for the SDK `>= 1.3.0, < 1.32.0` and the server package below 2.3.0. A high advisory, [GHSA-f897-62hf-6gxq](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-f897-62hf-6gxq), covers missing body and batch limits, for the SDK `>= 1.10.0, < 1.30.1` and v2 server and node packages below 2.1.0. Older high advisories cover shared-instance leaks through 1.25.3, a URI-template ReDoS below 1.25.2, and DNS rebinding protection disabled by default below 1.24.0. Whether later pages name 1.32.2 or 2.4.0 is unverified. No new vulnerability scan was run. The current default of DNS-rebinding protection inside 1.32.2 was not re-read in source.

Secrets: the packages do not ship an account or a key. OAuth helpers can store `refresh_token`, `client_secret`, and related client information if an application turns that path on. The product already keeps child env off the app env for stdio MCP. No secret was read or written for this check.

Integration: the product manifest already names `@modelcontextprotocol/sdk` at `^1.32.2`, and the product lockfile pins 1.32.2. The present `node_modules` copy also reports 1.32.2. This research did not install that copy and does not approve it. Product code imports `Client`, `StdioClientTransport`, `McpServer`, and `WebStandardStreamableHTTPServerTransport` from that package. Vendored upstream trees name older ranges, including `^1.29.0` and `1.30.0`, and those are not the product pin. v2 packages are not in the product manifest. Adding them would be a second client and server stack, not a drop-in bump of 1.32.2. Eve and every bot still share one workspace memory. This SDK is a protocol library, not a second brain. It must not gain its own memory, secrets store, or halt switch.

Compatibility: the product TypeScript range is `^5.7.0` and `zod` is `^4.4.0`, which satisfies the 1.32.2 peer range and the 2.4.0 `zod` range. The sandbox Node is v22.23.4, which meets both `>=18` and `>=20`. The product already uses the v1 import paths. Whether a Vite preview still bundles a later 1.x or a v2 package is unverified. v2 changes package names, Node floor, and schema style. The README says v1 keeps bug fixes and security updates for at least six months after the v2 release dated 2026-07-27. A separate end date was not published on that page.

Risks: an MCP client can call tools on a server, and an MCP server can expose tools. The product stdio path can spawn a child, so a later trial can run a binary if an allowlist entry permits it. The existing note in product code says registration alone must not run a binary, and an empty `MIND_MCP_STDIO_ALLOW` refuses stdio. Allowed paired actions remain only `file_read`, `file_write`, `file_delete`, and `terminal`, and only after the owner approves that exact action. Halt blocks all four. Mouse, keyboard, browser pointer, and the Windows desktop stay blocked. The SDK must not become a side path around those gates. OAuth can send credentials to a server-named authorization server unless the application pins the issuer. Shared HTTP transports have leaked one client's messages to another in older v2 builds. `main` moved past the 2.4.0 release, and the private root version `2.0.0-alpha.0` is not the published 2.4.0 packages. No code review of 1.32.2 or 2.4.0 was done. The face file `public/brand/eve-idle.jpg` was not replaced.

Maintenance: the official docs list this repository as the Tier 1 TypeScript SDK. Tier 1 requires a stable release, issue triage within two business days, and critical bug resolution within seven days. Whether those clocks are met was not measured. npm publishes through GitHub Actions trusted publisher. The 2.4.0 release and the 1.32.2 package were both published on 2026-10-23. `main` still showed a commit dated 2026-11-10 in the commits list, while the repository card's `pushed_at` stayed 2026-10-31. v1 support beyond the README's six-month sentence is unverified. The project author on `main` is Model Context Protocol a Series of LF Projects, LLC. The published package author field still says Anthropic, PBC.

Rollback: do not add `@modelcontextprotocol/server`, `@modelcontextprotocol/client`, or `@modelcontextprotocol/core` to the product manifest or lockfile. Do not bump `@modelcontextprotocol/sdk` off the existing 1.32.2 pin in this pass. If a later trial adds a v2 package, remove that package and reinstall from the previous lockfile. This research installed nothing, so it leaves no new package to remove.

Classification: evaluation-only. Identity is confirmed by the official SDK page and the matching GitHub repository. The MIT and Apache-2.0 terms do not block a paper review. The published advisory ranges found here do not include 1.32.2 or 2.4.0, so security does not block a paper review. It is not approved and not installed by this check.
