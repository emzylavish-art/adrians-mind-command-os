# Stagehand

Candidate id: stagehand. Name: Stagehand. Classification: evaluation-only. This note does not approve or install it.

Official source: [browserbase/stagehand](https://github.com/browserbase/stagehand). The repository is public, not archived, and not disabled. Its homepage field is [https://stagehand.dev](https://stagehand.dev/). The README describes the SDK for browser agents, owned by the Browserbase organization, and points to [docs.stagehand.dev](https://docs.stagehand.dev/). The LICENSE copyright holder is Browserbase Inc. The README also says "Stagehand" is a trademark of Browserbase, Inc. This is the official Browserbase project. It is not the separately listed `@browserbasehq/stagehand-docs` package.

Version: the candidate version is the published TypeScript package `@browserbasehq/stagehand` 4.4.0. npm `latest` is 4.4.0, published 2026-11-04T17:20:39.326Z. PyPI `stagehand` latest is also 4.4.0, uploaded 2026-11-04. `CHANGELOG.md` on `main` starts at TypeScript SDK 4.4.0 and Python SDK 4.4.0. There is no git tag `v4.4.0` and no git tag `@browserbasehq/stagehand@4.4.0`. GitHub `releases/latest` is not the SDK. It is `stagehand-server-v3/v3.7.7`, published 2026-10-23T18:09:00Z, not a draft and not a prerelease. The site badge still says Stagehand v4.0.0. That is a product line, not the current package version. npm also has dist-tag `v3-latest` at 3.7.3 and dist-tag `alpha` at `4.4.1-alpha-6f2686d792b7f5836b04754e0f6a44db39928592`, whose prefix matches the `main` commit `6f2686d792b7` from 2026-11-14T00:20:58Z. Those alphas are not the candidate. The Go module proxy latest is `v4.3.0`, dated 2026-10-20T00:24:52Z, tag `packages/sdk-go/v4.3.0`, commit `621c120639a230dbf401965cb250f7c47da96b9c`. The install page still shows `go get ...@v4.0.0`, which is older than both the proxy latest and the TypeScript package. The `browse` CLI on npm latest is 0.11.4, published 2026-11-13T00:35:39.186Z, and the git tag `browse@0.11.4` exists. That CLI is not the SDK candidate.

License: MIT, copyright 2024 Browserbase Inc. The LICENSE file on `main` matches the MIT text. The published npm 4.4.0 record says MIT. PyPI `stagehand` 4.4.0 has license expression MIT. The license allows use, modification, and sale if the copyright and permission notice stay with copies. It gives no warranty. The trademark line does not turn the code license into a commercial block. The LICENSE blob at the exact unpublished 4.4.0 commit was not compared, because that commit is not tagged.

Commercial: the SDK is free to use under MIT. Browserbase cloud is a separate paid service. On 2026-11-15 the pricing page listed Free at $0 with 3 concurrent browsers, 1 browser hour, 3 agent runs, 1,000 search calls, 1,000 fetch calls, 15 minutes per session, $5 of model tokens, captcha solving off, and 7-day retention. Developer was $20 a month with 25 concurrent browsers, 100 browser hours then $0.12 per hour, 15 agent runs, 1,000 search calls then provider-specific rates, 1,000 fetch calls then $1 per 1,000, 1 GB of proxies then $12 per GB, captcha solving, basic stealth, and 30-day retention. Startup was $99 a month with 100 concurrent browsers, 500 browser hours then $0.10 per hour, 50 agent runs, 10,000 fetch calls then $0.50 per 1,000, 5 GB of proxies then $10 per GB, and 30-day retention. Scale was custom, with 250 or more concurrent browsers, verified agents, advanced stealth, SSO, and HIPAA BAA and DPA. Model Gateway is billed at market price on the paid columns and is only available on Browserbase-hosted browsers. Local runs still need a model provider bill unless the caller supplies a callback. Exact Adrian Mind usage is unverified. This research created no account and spent no money.

Activity: at check time the GitHub repository showed 26,055 stars, 1,823 forks, and an open-issue count of 439. That count includes pull requests. `created_at` was 2024-03-24T19:19:44Z. `pushed_at` was 2026-11-14T01:25:38Z. The newest `main` commit seen was `6f2686d792b7`, dated 2026-11-14T00:20:58Z. npm recorded 2,620,551 downloads of `@browserbasehq/stagehand` from 2026-11-08 through 2026-11-14. The site star badge said 23.7k on the same day. The API count is the one used here. The maintainer list includes `@browserbase.com` addresses. Company funding and headcount were not checked.

Runtime: version 4 is a TypeScript, Python, and Go SDK that drives Chromium over the Chrome DevTools Protocol. The 4.4.0 npm record does not depend on Playwright. Docs say local runs need Chrome installed, and the 4.4 watchdog needs Chrome 137 or later. Cloud runs use `browserbase.launch()` and a Browserbase API key. The same script can also attach to an already running browser with `localBrowser.connect()`. Node.js 22.18 or later, Python 3.11 or later, or Go 1.26 or later are the documented runtimes. The Go `go` line inside module `v4.3.0` was not fetched, so that Go requirement is unverified against the module file. None of this was executed.

Install size: not measured on disk, because nothing was installed or pulled. The published npm 4.4.0 record reports an unpacked size of 4,139,595 bytes across 16 files. The PyPI 4.4.0 wheel is 636,668 bytes and the sdist is 622,700 bytes. Those figures do not include Chrome, the transitive `@browserbasehq/sdk` package, or OpenTelemetry packages. GitHub reports the repository size as 207,157 KB. That is not an installed footprint.

Dependencies: npm 4.4.0 depends on `zod` exactly `4.6.6`, `@browserbasehq/sdk` `^2.16.0`, `@opentelemetry/api` `1.9.1`, and `@opentelemetry/core` `2.9.0`. It has no peer or optional dependencies and no bin. Its published scripts are test and build scripts. They do not include `preinstall`, `install`, `postinstall`, or `prepare`. The install page still tells TypeScript users to add `zod@~4.4.3`, which does not match the published pin of `zod` `4.6.6`. Python 4.4.0 requires `browserbase`, `httpx`, `opentelemetry-api`, `pydantic`, `typing-extensions`, and `websockets`. The `browse` CLI 0.11.4 depends on `@browserbasehq/stagehand` `4.4.0`. Transitive dependency risk was not audited.

Security: OSV `MAL-2025-191198` and GitHub advisory [GHSA-mmp7-557c-74pq](https://github.com/advisories/GHSA-mmp7-557c-74pq) say `@browserbasehq/stagehand` version `3.0.4` contains malware. The affected range is exactly `3.0.4`. The patched-version field is empty, and the advisory is not withdrawn. The npm time record for 3.0.4 is 2025-11-24T12:56:32.742Z, but the version document is absent from the registry, so that tarball is not currently published. Version 3.0.5 remains published and is not listed in the malware advisory. Version 4.4.0 is not listed either. No malware scan of the 4.4.0 tarball was run, so absence from that advisory is not a clean-bill scan. A different advisory, [GHSA-4rjx-92xj-8cj8](https://github.com/advisories/GHSA-4rjx-92xj-8cj8), covers `@browserbasehq/stagehand-docs` `1.0.1`, not this package. The repository security-advisories list was empty. Changelog entry `#3387` in 4.4.0 says domain-policy bypasses through credential URLs, background requests, and speculative loads were fixed. Whether any later bypass remains is unverified. [CVE-2026-12823](https://github.com/advisories/GHSA-vxfm-r32r-fgx3) is an unreviewed low local-permission report about a Browserbase Autobrowse trace artifact. It names no package, so it is not treated as covering `@browserbasehq/stagehand` 4.4.0.

Secrets: a Browserbase run needs `BROWSERBASE_API_KEY`. Direct model calls need that provider's key. The docs say Stagehand does not read environment variables for you. The README shows an `observe()` then local `fill()` pattern so a password string is not placed in the model prompt. That is a usage pattern, not an enforced control. `act()`, `extract()`, and `observe()` send page context to a model, and extract can include screenshots. The context API can read cookie values. `userDataDir` persists a signed-in profile on disk. Browserbase sessions can record, and the pricing page lists 7-day retention on Free and 30-day retention on Developer and Startup. Hosted MCP at `https://mcp.browserbase.com/mcp` also takes the Browserbase key. No secret was read or written for this check. No installer script was run.

Integration: Adrian Mind does not import Stagehand. The product `package.json` and `package-lock.json` have no Stagehand or Browserbase dependency, and `src` has no Stagehand reference. Vendored trees under `upstream` mention older Browserbase packages, including a lock entry for `@browserbasehq/stagehand` 1.14.0. Those trees are not the product dependency and were not changed. Adding Stagehand would be a new browser-control path, not an upgrade of Chat, Build, or Speak. It was not added.

Compatibility: the product TypeScript range is `^5.7.0` and `zod` is `^4.4.0`, which can resolve `4.6.6`. The product manifest has no `engines` field. The sandbox Node is v22.23.4, which meets the SDK's `>=22.18.0`. The product already has Playwright `^1.62.0` as a dev dependency. Version 4 docs say Stagehand itself does not depend on Playwright. Whether both can run in the Vite preview was not tested. The product model is Grok. The v4 model page lists five native providers, Google, Anthropic, OpenAI, Groq, and Cerebras. xAI is not in that list. A client-side LLM callback exists. Whether that callback can wrap the saved Grok key is unverified. Model Gateway does not work with a local browser.

Risks: `act()` can click, type, and navigate. That is browser control, which the current owner flow does not include. A cloud model or Browserbase session can take page contents, cookies, and recordings outside the preview. `setDomainPolicy(null)` clears the policy, and the reference does not say a deny-by-default policy is on when none is set. Version 4.4 closed named domain-policy bypasses, but the package was not reviewed here. The unpublished 3.0.4 malware version must not be installed, and a floating range that could select it must not be used. npm `latest` is ahead of every git tag found for the SDK, and `main` already publishes 4.4.1 alphas, so a later trial has to pin 4.4.0 rather than track `main`. `localBrowser.connect()` can attach to a browser the user already has open. `disconnect()` with `keepAlive` can leave that browser running. No code review of 4.4.0 was done.

Maintenance: Browserbase publishes the repository. npm `latest` was published 2026-11-04, and `main` moved again on 2026-11-14. SECURITY.md says fixes go to the latest release of each published package: the npm package, the PyPI package, the Go module, and the `browse` CLI. Support beyond that policy page is unverified. The Go module latest is still 4.3.0, so the three languages are not on one version.

Rollback: do not add `@browserbasehq/stagehand`, `stagehand`, or the `browse` CLI, and do not start Chrome or a Browserbase session for it. If a later trial does, remove the added package from the manifest, stop the Chrome process it launched, delete the user-data directory it created, and close or disconnect the Browserbase session created for the trial. Nothing was installed, so there is no package or browser to remove.

Classification: evaluation-only. Identity is confirmed. The MIT license does not block review. The malware advisory covers 3.0.4 only, and 4.4.0 is outside that range, so this candidate is not blocked by that advisory. It is not approved and not installed.
