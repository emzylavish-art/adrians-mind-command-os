## Implemented behavior and integration invariants

- **Notion and receipts:** operation identity binds owner, workspace, destination and content. Accepted or uncertain writes recover by verification; reconnect and retry cannot create a second append or transfer approval to another workspace. Durable receipt recording is transactional and retryable after a failed save. The actual chat handler is exercised with the real adapter and synthetic provider/store dependencies, including a workspace change before approval or recovery.
- **Connections and shared limits:** the Plugins DTO retains grant/expiry evidence; refresh uses a bounded claim and rechecks connection identity; local disconnect is distinct from provider revocation and keeps unresolved revocation evidence. Configuration readiness stays distinct from live operational health. Shared SQL request windows and per-dispatch gates are used by the affected production entry points.
- **Fleet and approval:** saved plans/dependencies are consumed explicitly, incomplete plans cannot claim completion, approvals bind the operation, emergency stop gates new dispatch, missed-run policies and outcome records are explicit, and restore/import cannot grant execution or conversation-delivery authority.
- **Data continuity and privacy:** stale archives preserve newer metadata, deleted-file tombstones, disabled schedules, terminal runs and divergent note history. Project deletion unlinks dependent objects. Library deletion explains copies retained in conversation history. Persona origin, account identity and a five-minute handoff boundary survive normalization and storage failures.
- **Provider and voice choices:** selected models retain capability/pricing uncertainty and current authorization; helper fan-out has consent, concurrency, result/failure receipts and separate source identities. Speak treats input, answering and speech output as separate stages, fences late responses and reports the current turn's actual answering receipt. No fixture is presented as a real provider or audio-device response.
- **Research, files and retrieval:** research preserves route/query/source provenance and states evidence maturity; retry preserves provider identity. Images, PDFs, local notes and project results retain relevant identity and truncation evidence. Search supports independent terms, quoted phrases, every matching message, scope labels and an incremental normalized index; it does not claim measured live-device latency.
- **Dashboard and interface:** fallback/reduced-motion/graphics recovery paths preserve meaningful state; spend labels identify telemetry limits. Modal semantics and native focus behavior are centralized, palette pinning is visible, shortcuts match the OS, and the drawer uses actual shared theme tokens. Synthetic component fixtures are distinct from real GPU, browser, screen-reader or physical-device verification.

See [verification.md](verification.md) for the final commands, results, failures, skips and reproduction instructions. The full application graph and production artifact build passed; the full-repository TypeScript attempt and changed-source lint did not pass.

## Migrations and shared-file reconciliation

Two additive migrations are included:

- [0018_c2_execution_recovery.sql](../../../migrations/0018_c2_execution_recovery.sql) adds durable receipt, rate-window, Notion operation, OAuth recovery and refresh-claim records, safe tool-run metadata, and OAuth expiry/scope evidence.
- [0019_c2_model_profiles.sql](../../../migrations/0019_c2_model_profiles.sql) adds model capability profiles alongside the existing model-ID representation.

The database fixtures applied these migrations to disposable local databases. **No production migration ran here.** Reconcile migration numbering and prerequisites with the other audit branches, then test the combined current schema and later authorized rollout order. Execution correlation metadata uses an explicit bounded allowlist. Owner scoping and retention must remain intact when combining the schema. A deployment must not start reading these columns before its migration gate succeeds.

The broad shared files are `command-app.tsx`, `server.ts`, `fleet.ts`, `workspace.ts`, `types.ts`, `turn.server.ts`, `policy.ts`, `provider-catalog.ts`, `ai-provider-config.server.ts`, `use-mind-workspace.ts`, `package.json` and the test runners. A clean textual merge does not establish compatible behavior. Preserve these cross-branch invariants:

1. A Notion recovery retains its original operation, owner, workspace and destination, and uses `confirmed: false`; an uncertain outcome cannot replay a write. A changed chat workspace blocks the captured approval/recovery before dispatch.
2. OAuth refresh/reconnect and archive restore cannot revive a disconnected grant, copy old authorization to a new identity, or transfer action approval. Revocation uncertainty remains visible after local disconnect.
3. Consultation and every provider dispatch preserve current consent, free-only restrictions, capability uncertainty and shared rate gates. Unknown price is not free, and selected provider/model identity is not silently substituted.
4. Voice input, answer and output selections remain distinct; abort/mute/session changes fence delayed results and current-turn attribution cannot reuse an earlier receipt.
5. Archive normalization and merge preserve revisions/tombstones while restored execution authority stays inactive. A schedule's imported delivery target cannot acquire or redirect a local approval.
6. Persona template origin, account/workspace identity and atomic handoff must survive other bot/fleet normalization changes.
7. Normal test discovery and shards derive from the same inventory, include script tests intentionally, reject invalid/empty selections, and retain distinct regressions from the other branches.
