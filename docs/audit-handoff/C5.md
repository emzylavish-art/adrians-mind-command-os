## Integration concerns and remaining release gates

- **Shared hotspots:** command-app combines account, selection, memory, catalog, MCP, stop and voice changes; workspace combines memory/archive/bot/usage semantics; turn.server combines dispatch identity and accounting. Also reconcile auth, provider adapters, fleet/worker and generated routes across branches even if Git merges cleanly. Keep distinct regression tests. No known overlap is silently dropped.
- **Privacy:** memory revision must describe the same source/chat snapshot used to construct the request. Do not compare current-state hash to an older body. A new request after privacy change gets a new operation identity; existing transcript content and already-sent content cannot be recalled by switching Memory off.
- **Archive compatibility:** preserve legacy integrity before adding optional normalized metadata. Missing scope requires review; invalid explicit scoped associations cannot silently become global. Replace must quarantine against its resulting workspace, not destinations that are about to disappear. Conservative Merge and privacy defaults are explicit product choices.
- **Voice:** preserve the one-answer composed path, separate declared STT/TTS providers, no key-inferred fallback, actual attribution and delayed cancellation/mute guards. Native xAI remains explicit. Browser recognition can use browser-managed services. Handy rejects an explicitly unsupported browser path rather than silently uploading elsewhere.
- **Ownership and MCP:** canonical identity must land with expected-owner checks and sensitive remounts. Matching email/name is not account linkage. Capability refresh, fingerprinted approval and exact review are one contract; changing arguments/schema/host/credentials requires fresh approval.
- **Migration:** `migrations/0020_c5_usage_ledger.sql` creates independent `mind_usage_ledger`, primary key `(user_id, operation_id, stage)`, and owner/time index. Reconcile numbering with other audit branches and apply via normal migration runner in an authorized environment. History begins when recorded; missing old usage cannot be invented.
- **Accounting scope:** reported tokens are not a verified financial charge. Preserve unknown counts, stage identities and completed metadata. UTC daily/monthly/provider/channel grouping and full/partial selected-period export are implemented. Owner-confirmed retention reviews matching count, exact typed UTC cutoff, CSRF and expected-owner state, then deletes at most 1,000 records strictly before cutoff; no automatic cleanup and no turn-receipt deletion. Unknown response invalidates the review to prevent confirmation reuse. Real invoice matching/pricing remains unsupported evidence rather than an estimated bill. Build runtime progress and native realtime authorization remain explicitly separate from provider-answer/token proof.
- **Hosted worker:** `/api/mind/schedules/tick` requires `MIND_SCHEDULE_WORKER_TOKEN` at least 32 characters and an external authorized POST scheduler. Neither was configured. It runs bounded local tools; paid/external/model stages retain their separately reviewed execution. Prove browser-closed operation and heartbeat aging only after authorized activation.
- **Native provenance/cancellation:** submitted source hashes do not prove the native runtime executed them. AA020 needs separate companion protocol/readback and physical verification. Cancellation requested is not termination confirmed. Preserve pending/unknown status and do not restart work when stop is released.
- **Routes:** preserve/regenerate `src/routeTree.gen.ts` for new usage and schedule routes while retaining other branches’ additions.

Before consolidated release: run full normal tests, semantic typecheck, applicable lint/build; reconcile and apply usage migration to disposable integration database; exercise account/cross-tab/provider/MCP/Notion navigation with controlled transport; test mounted voice/Build stop and reload; then separately authorize provider/device/worker validation.
