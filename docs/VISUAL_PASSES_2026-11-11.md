# Twenty visual passes — 11 November 2026

Each pass covers every page that was opened: Chat, Dashboard, Explore, EVE, Bots, 3D Graph, Build, Projects, Research, Library, Thread, Runs, Connected, Tools, Skills, Scheduled, Memory, Activity, Settings, and Help. A pass is a new focus, not a new sidebar click. The public alias was still the paper build during the walk. The compact composer and row surfaces are in the working tree, not on the public alias yet.

## 1. First screen

Chat spends the first screen on a greeting, a dead portrait, and three stacked control cards before the question field. GPT, Grok, and Manus put the field first. Every other page opens with a poster heading and a sentence, then the controls.

## 2. Hierarchy

No page has one primary action. Chat has Ask, Automatic, Memory, mode, routing, effort, style, and Send at the same size. Connected gives every service the same card. Build gives Refresh the same weight as the title.

## 3. Empty states

Projects, Runs, Library, and Research say the thing is empty, which is honest. They still look like unfinished cards because the empty line sits inside the same poster frame as a filled page.

## 4. Button language

Setup on the public Connected page repeats a sentence instead of opening a field. Connect Google says coming soon. Skills has Turn off on tools that are not running. The local fix opens the paste form and gives each plugin an Add button.

## 5. Truncation

Sidebar labels cut at EVE / Intelligence, Scheduled, and recent chat titles. The model chip cuts the model id. Activity codes were raw until the label map. The header search shows only a shortcut.

## 6. Contrast

The white Ask card is the only high-contrast control. Everything else is gray on gray. Status pills and body text use the same muted color, so connected and not connected look alike until you read the sentence.

## 7. Spacing

Controls stack with the same gap as paragraphs. There is no tight group for mode and a loose group for status. The composer tools wrap into a second and third row with no label for the group.

## 8. Cards versus rows

The public Connected page is a three-column wall of identical cards. Tools, Skills, and Research repeat the same paper row. A row with a name, a status, and one button is the shape those products use. The local board is a list plus one detail pane.

## 9. Status honesty

Gmail, Drive, Calendar, YouTube, GitHub, and Notion have real server states on the public page. The visual does not separate those from Docs, Slack, and the missing API keys. A green edge or a single word is missing.

## 10. Error copy

The public activity list shows forbidden_cross_site. Build shows a raw server path for the missing companion directory. Notion failures repeat the same line five times. The label map now says Blocked a cross-site request and Notion search failed. Build no longer prints the path.

## 11. Forms

API, MCP, and mailbox fields exist, but they sit under the card wall on the public page. Labels are present. The fields are not the first thing a Setup click reveals until the newer build is the alias.

## 12. Icons

The sidebar uses the same systems icon for Connected, Tools, Skills, Scheduled, Settings, and Help. That makes the list a column of identical marks. Chat, Build, and Research have distinct icons. The rest do not.

## 13. Header

The top bar holds view name, voice mode, Grok configured, the model chip, alerts, and the account chip. The model chip is the one that truncates. Search is a second bar under it, so the header is two rows before the page starts.

## 14. Sidebar

Twenty destinations plus search, recent chats, New, account, and storage are in one column. The account row collides with New at the bottom of a short viewport. Storage is a second sentence under the account. A product sidebar keeps the account pinned and lets the list scroll.

## 15. Loading

3D Graph says Painting the universe and then Loading 3D graph. EVE's portrait stays a black square. Chat shows Checking in the header while Notion status is still unknown. Loading is a sentence, not a stable skeleton in the place the content will land.

## 16. Duplication

Kimi login is printed twice on the public Connected page. Chat and Thread are two chat surfaces. Dashboard and 3D Graph both claim a graph. The local tree removes the second Kimi block.

## 17. Below the fold

Chat cuts Attach, Image, Send, and the suggestion chips on the public page. The compact local composer keeps Send on the first screen. Projects, status, and activity still continue under it. Those belong under the fold, not beside the field.

## 18. Identifiers

Scope names, ISO timestamps, and migration paths leak into owner-facing lines. GitHub shows read:user,repo and a timestamp. That is accurate and ugly. A mailbox or account name plus Connected is the label. The scope can live in the detail pane.

## 19. Consistency

Chat, Connected, Build, and Research do not share a header size, a button height, or a status word. The sharp surface flattens the poster cards. It does not yet give every page the same title row and the same primary button.

## 20. What a new owner cannot tell

A new owner cannot tell which buttons save a connection and which buttons only explain. They cannot tell that Slack is intentionally off. They cannot tell that Build will not edit files on this host. The sentences exist. The layout does not make those three facts the first thing on those pages.
