## Compatibility, overlap and release boundaries

- Shared integration points are `command-app.tsx`, `types.ts`, `workspace.ts`, `server.ts`, `turn.server.ts` and `prompt.ts`. Preserve connector identity guards, request receipts and media compaction while reconciling other branches.
- Completed operation recovery must precede new-dispatch privacy validation. A revoked context blocks a **new** provider operation; it must not prevent retrieving an already stored result under its original ID.
- New bot/document/context-bearing sends must save the current privacy state first. Authenticated server validation must still re-read it. A client save or revision alone is not authority.
- Batches retain per-request owner locking and optimistic revision checks. An interrupted multi-batch import has a confirmed prefix and an intact browser copy; the next attempt computes the remaining changes. It is not one atomic transaction spanning every batch.
- The legacy full checkpoint and normalized mirror schema remain readable for compatibility. Moving all browser/server reads to paginated independently versioned records is a further **proposal needing a decision** about the final migration/retention contract; this branch does not claim that full snapshot reads or all browser serialization disappeared. A single exceptionally large message or conflict record still receives an explicit size error instead of an unbounded request.
- Original document bytes are stored on the originating browser, scoped by account. Their metadata syncs; their binary bytes do not become account/cloud backup. An exported JSON manifest explicitly says which originals are excluded. Cross-device binary storage requires an authorized storage backend/retention decision and is not claimed here.
- Document citations identify exact **extracted-text character ranges** and the verified ordered page-tree PDF index where available. Missing/scanned/unsupported content retains explicit unavailable or unknown attribution. OCR and external-provider citation correctness remain outside the proved fixture boundary; page numbers are never inferred from arbitrary text offsets. See the runtime lane completion evidence (31/31 PDF/knowledge/original/render tests).
- Live multi-tab/device behavior, authenticated account changes during asynchronous hydration/upload, accessible confirmation focus on a real browser, and live provider response/citation behavior remain release checks. Synthetic receipt/IndexedDB fixtures do not establish those results.
- Native installers, Windows applications and production deployment/settings are untouched by this lane.
