## Scoring rules applied

Nothing in this matrix is `VERIFIED`. A row is `VERIFIED` only after an end-to-end test against a real Kimi runtime. No such test, log, commit, or acceptance record exists in this tree.

Local fake ACP smoke tests are `PARTIAL`. `docs/KIMI_CODE_PHASE_1_HANDOFF.md` states that the local smoke used a fake ACP process and a mock dashboard. That smoke does not prove that Kimi is installed, logged in, or executing.

Windows Companion code is `PARTIAL` and is not the website release. The website-first rule requires a hosted runtime that does not need the user's Windows PC. Companion files under `agent/windows/` do not satisfy that release.

`src/lib/mind/kimi/capabilities.ts` uses `fully_integrated`, `limited`, `not_supported`, and `planned`. Those words are not this matrix. `GET /api/mind/kimi/capabilities` also returns `runtimeVerified: false`.

## Current boundary

The website is an authenticated control plane. `POST /api/mind/kimi/session` queues a `kimi-acp` job for the first online paired Windows agent. File operations queue `file-op` jobs. If no Companion is online, the route returns 409 and the UI says nothing was executed. `agent/windows/MindAgent.ps1` launches `KimiAcpClient.mjs` only for `kimi-acp` and `file-op`. It rejects every other job kind, including the `shell` jobs created by the approved-terminal path in `src/lib/mind/pc-pairing/run.ts`. The ACP client sends `session/new` with `mcpServers: []`, denies ACP terminal reverse-RPC, and cancels ACP permission requests instead of opening an approval.

## Website release verdict

The website release is not available. The control plane can queue Companion work and can refuse to invent output, but it cannot create a hosted Kimi session, stream a real Kimi task, or pass the Part 16.11 scenario. Companion implementation remains a later target and is not evidence for that release.
