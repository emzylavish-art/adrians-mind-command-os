# Live section analysis — 11 November 2026

Site walked: https://adrians-mind.vercel.app/
This is the public production page. It is not the local preview.
No secret is recorded here.

## What the walk found

The sidebar opens a real page for Chat, Dashboard, Explore, EVE, Bots, 3D Graph, Build, Projects, Research, Thread, Runs, Connected, Tools, Skills, Scheduled, and Memory. Library, Activity, Settings, and Help exist as their own views in the code. A heading scan can still report Skills first because that section stays in the page and is only hidden.

The failure the owner keeps hitting is not a missing sidebar item. It is that Connected is a wall of identical paper cards. Setup repeats a sentence. It does not put the cursor in a key field. Connect Google is still marked coming soon on this public page even though Gmail is already connected.

## Section notes

Chat works. The last answered model chip shows grok-4.20-0309-non-reasoning. Speak is present. Memory is off until the owner turns it on. The composer has Ask, Research, Agent, Build, routing A–D, and effort chips. Those chips change the send path. They are not separate products.

Dashboard and Explore are links, not dead buttons.

EVE Workbench opens. Its buttons jump to Chat, Agents, run history, connections, and the 3D dashboard. Queue task is a local queue, not a hosted worker that has been proven in this walk.

Bots and Agents opens. Run REA doctor, lookup, and planner are real local tool actions. Add Personal assistant writes a local record. It does not prove a remote agent process.

3D Graph opens. The dark portrait area is still a flat canvas. It is not a working scene control.

Build opens. The honest line is on the page: a plan is not a file change. Companion is offline because the hosted function tries to create `/var/task/.data/mind-pc-pairing/agents` and that directory does not exist. Browse, Search, Register workspace, Save profile, Run with Kimi, and Plan with Grok are present. Registering a path does not prove the path is reachable. Agent, Timeline, Changes, Editor, Terminal, and Capabilities are panel tabs. They must not be described as a running Kimi editor.

Projects opens. New Project saves a browser record. There is no hosted project list yet.

Research opens. Check research and the REA actions are the working controls. The rest of the page still repeats the same Turn off / Run paper rows used by other sections.

Library is the files view. It reads text, markdown, CSV, JSON, and attached PDF text. It is not a second Skills page.

Thread opens the older AI Chat list, including the ready-check threads. It is a second chat surface, not a broken click.

Runs opens. Queue run and Run worker once are the real controls. A queued run is not a completed coding task.

Connected is the broken experience. The public page shows a three-column card grid. Grok, Notion, GitHub, Gmail, Drive, Calendar, and YouTube have a real server state. Notion says API token present. GitHub says read:user,repo since 2026-11-11T21:30:57Z. Gmail, Drive, Calendar, and YouTube say emzylavish@gmail.com. Docs, Slack, OpenAI, Claude, Gemini, OpenRouter, web search, image and video, MCP, and the local computer are not connected. Clicking OpenAI Setup did not open a focused paste field. It left the same paper card on screen. Slack Setup must not start a login. Connect Google at the bottom still says coming soon, which is false for the already connected mailbox and confusing for Docs.

Tools opens. Try SELECT 1 is the built-in database check. Save connection is an owner form. Open page is not a plugin installer.

Skills, Scheduled, and Memory open their own pages. Add daily job and Run due schedules are local schedule controls. Enable Memory and Save note are local memory controls. They are not Notion.

Activity, Settings, and Help are separate code views. They must not be reported as the Skills page just because a hidden Skills heading is first in the document.

## Plugins

On the public page, Kimi plugins are a bullet list under a login wall. There is no individual Add button. The same Kimi block is rendered twice, once after the service cards and once after the mailbox form. That is the paper look. Kimi’s own plugin screen is a tabbed list: Installed, Official, Curated, Custom, with one button per plugin that opens the install step.
