## 3. Current server and Companion contracts

### Kimi session API

`POST /api/mind/kimi/session` requires authenticated Adrian OS identity and same-origin protection. It selects an online paired agent, checks the emergency stop, validates a bounded prompt and optional workspace path, and queues a `kind: "kimi-acp"` job.

`GET /api/mind/kimi/session?jobId=...` returns the owner-scoped job status and bounded stored events. It will not return another owner’s job.

The Kimi job payload currently contains the prompt and optional `cwd`. The selected Companion must enforce the workspace root again; the server must not treat a user-supplied path as trusted merely because the request is authenticated.

### Kimi file API

`POST /api/mind/kimi/files` accepts one of:

```text
list
read
write
```

The request may include `cwd`, `path`, and `content` as appropriate. The server bounds path and content lengths, requires authentication and same-origin protection, checks the emergency stop, and queues a `kind: "file-op"` job to an online Companion.

`GET /api/mind/kimi/files?jobId=...` returns the owner-scoped file-operation job and events.

The Companion worker enforces the actual path boundary. It resolves the requested path beneath the selected approved workspace and checks it against every configured `allowedRoot`. It rejects path traversal and absolute paths outside the allowed roots. Workspace listing skips `.git`, `node_modules`, and `.data`, is capped at 500 files, and reports bounded file metadata. Reads and writes are capped at 1 MB. Writes return a JSON result containing `before` and `after` content so the UI can show a bounded review payload.

### Terminal approval API

`POST /api/mind/kimi/terminal` accepts a command and creates a short-lived owner approval record using the existing `src/lib/mind/pc-pairing/approvals.ts` infrastructure. It does not execute the command.

`POST /api/mind/pc/approve` consumes the one-time approval and calls the existing `runOnPairedAgent` path with `confirm: true`. The resulting shell job is executed by the Companion only when the job is explicitly confirmed. Reuse, mismatch, expiration, forged approval tokens, emergency stop, and no-agent cases are rejected.

The Companion shell implementation runs the command in the approved workspace, caps stdout/stderr, enforces a 120-second timeout, reports `terminal_start` and `terminal_complete`, and reports a bounded error for a nonzero exit. The worker refuses a shell job where `confirm` is not true. ACP reverse terminal requests are still refused; the supported path is the Adrian OS owner-approval route.

### Cancellation API

`POST /api/mind/kimi/cancel` requires the owner and same-origin protection. It changes a queued job to `cancelled`, or a running job to `cancel_requested`.

The Companion’s active Kimi worker polls `GET /api/mind/pc/jobs?jobId=...` with the device token. When it sees `cancel_requested`, it records a cancellation event and terminates the child process. The server’s completion path prevents a late result from changing a cancelled job back to success. The local cancellation smoke test verified that an active ACP child is terminated and reports failure honestly.

### Companion queue and event API

`GET /api/mind/pc/jobs` with the device bearer token claims the next queued job for that device. A `jobId` query returns the device-bound status used by cancellation polling. `POST /api/mind/pc/events` accepts token-bound events. `POST /api/mind/pc/result` accepts token-bound completion results. These paths are not public unauthenticated runtime endpoints.

The store supports these job kinds:

```text
shell
kimi-acp
file-op
```

It supports these lifecycle statuses:

```text
queued
running
cancel_requested
cancelled
done
error
timeout
```

Keep the queue/event bounds, owner checks, device binding, emergency stop, signed manifest, and redaction behavior intact when extending the system.

## 9. Security invariants that must not regress

The next Manus must treat these as non-negotiable:

1. No unauthenticated public runtime endpoint.
2. No API keys or Companion bearer tokens in frontend code or logs.
3. No path traversal or workspace escape, including Windows drive/path edge cases.
4. No unrestricted shell execution. Commands require the existing owner approval record and explicit `confirm: true` server authorization.
5. No bypass around emergency stop, revocation, token binding, manifest integrity, or same-origin protection.
6. No late result may turn an owner-cancelled job into a successful job.
7. No fake Connected, Completed, file contents, terminal output, or Kimi capability labels.
8. No private chain-of-thought rendering. Display progress summaries, tool lifecycle, decisions, outputs, and errors only.
9. Keep event sizes, output sizes, prompt sizes, file sizes, listing counts, and timeouts bounded.
10. Preserve owner and device checks on every job, event, result, status, approval, file, terminal, and cancellation path.
11. Never assume that Adrian OS authentication equals Kimi CLI authentication.
12. Never deploy or run production migrations without explicit user authorization.
